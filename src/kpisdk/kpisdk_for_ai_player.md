# kpisdk の補足（AI 向け）：演奏プラグイン

kpisdk_for_ai.md（入口）の続きです。先に入口の「読み方」と 0 節（設計の考え方）を読んでください。
節の番号は全ファイルを通した番号です（「6-1」はデコーダプラグインの 6 節の 1）。
ほかの節がどのファイルにあるかは、入口の「節の一覧」にあります。

## 7. 演奏プラグイン（IKpiPlayer）

この節は、演奏プラグインの仕様 v4（KPI_PLAYER_MODULE_VERSION 4。v3.17beta7 以降の本体）についてです。
本体は KPI_PLAYER_MODULE_VERSION が一致しない演奏プラグインを読み込まないので、v4 のプラグインは v3.17beta6 以前の本体では使えません。

### 7-1. 演奏プラグインにする形式

- 使うライブラリやプログラムの構造のせいで、デコーダプラグインにできない形式（PCM を受け取れず、演奏の指示しかできない形式）のためのものです。
  PCM を受け取れる形式は、デコーダプラグインにしてください。動画も、デコーダプラグインで扱えます（6-15 の IKpiVideoWindow）。
- 音の出力までプラグインが行うので、次のものは効きません：本体の出力の設定（出力プラグイン・WASAPI 排他・ASIO・形式の変換など）、
  本体の音の処理（イコライザ・エコー・リプレイゲイン・プラグインごとの音量など）、ギャップレス再生、ディスクへの書き出し。
  スペアナは、本体が Windows のプロセスループバックで音を取り込んで表示します（Windows 11 から）。
- フェードイン・フェードアウトは、本体が約 200ms ごとに SetVolume を呼んで作ります。音量を変えられない曲は、GetCaps で
  KPI_PLAYER_CAPS_VOLUME を返さないでください（本体はフェードアウトせずに止めます）。

### 7-2. 本体の呼び方

- 開いてから演奏するまで：Open → Select（曲番号 1 から） → GetCaps → （CreateVideoWindow。7-4） →
  （自分のウィンドウなら SetWindowPosition） → SetTempo・SetPitch・SetVolume・SetRepeat → Play。
  SetTempo などは Play の前にも呼ばれるので、値を覚えておき、演奏を始めるときに反映してください。
  - SetVolume・SetTempo・SetPitch は、GetCaps で KPI_PLAYER_CAPS_VOLUME・TEMPO・PITCH を返した曲にだけ呼ばれます。Select の前には呼ばれません（v3.17beta7 以降。
    それより前の本体はフラグに関わらず、Select の前にも呼んでいました）。
    決まり：対応しない場合も、呼ばれたら何もしないでください（ほかのアプリからは呼ばれることがあります）。
- 演奏中は、約 50ms ごとに GetStatus と GetPosition を呼びます。時間のかかる処理はしないでください
  （例えば、自分のスレッドへの指示にせず、スレッドが書いた値を返すだけにする）。
- 設定が変わったら、次の GetStatus・GetPosition の前に UpdateConfig を呼びます。
- Play を呼んでから 1 秒間は、GetStatus が STOP・ERROR を返しても演奏中とみなします（ライブラリが演奏を始めるのが遅れる場合のため）。
- 曲の終わりは GetStatus の STOP で知ります。単曲リピートでは、本体が Play で先頭から演奏し直します（SetRepeat に対応しなくてかまいません）。
- KPI_STATUS_ERROR（(DWORD)-1）を返すと、本体は次の曲へ進みます。単曲リピートでも、同じ曲を開き直さずに演奏を止めます。
  ファイルやライブラリのエラーで演奏を続けられないときに返してください。
  - Play が失敗した（演奏を始められなかった）ときも、その後の GetStatus は STOP ではなく KPI_STATUS_ERROR を返してください。
    STOP だと本体は最後まで演奏したとみなし、単曲リピートでは同じ曲を開き直して、また失敗することを繰り返します。
  - 理由は、本体のメッセージログで利用者に知らせられます（8）。
- シーク：本体は Play（開始位置）で行います。演奏中・一時停止中に呼ばれたら、その位置から演奏し直してください。
  シークに対応しないなら、今の位置より前が指定されたら先頭から演奏し直し、後ろが指定されたら何もしないでください。
- 停止：Stop の後、本体の「停止時に隠す」がオンのときだけ SetVisible(FALSE) を呼びます（自分のウィンドウの場合）。
- 本体は、本体の中で動く演奏プラグインの呼び出しに時間の上限を設けていません。プラグインの中で待ち続けると本体も固まります（7-3）。
- タグ取得用の Open（cpRequest が NULL）は、dwSupportTagInfo に TAG_TITLE がある場合だけ呼ばれます
  （cszMultiSongExts に入れた拡張子のファイルは、曲の数を得るために TAG_TITLE がなくても呼ばれます。6-8）。その後は
  Select(曲番号, NULL, pTagInfo, …) だけが呼ばれ、演奏はされません。演奏リストの情報集めなどでファイルごとに呼ばれるので、
  スレッド・ウィンドウ・デバイスなどは作らず、軽く済ませてください。本体はこの Open と Select の戻り値を、そのファイルを開けるか
  （アーカイブの中のファイルを演奏リストに加えるかなど）の判断にも使うので、開けないファイルなら 0 を返してください。
  - 決まり：再生できるファイルなら、タグを取得できなくても（TAG_TITLE を立てていなくても）成功を返してください。Select はタグを渡さずに
    曲番号を返せば足ります。本体が呼ばない場合でも、ほかのアプリなどが呼ぶことがあるので、「cpRequest が NULL だから 0」としてはいけません。
  - 再生できるかを軽く確かめられない形式（外部の部品を読み込まないと分からないなど）は、部品が使えるかなどの最低限の確認で成功を返してかまいません。
    実際に開けるかは、再生のために開いたときに分かります。

### 7-3. スレッドと固まらない作り

- 各メソッドは同じスレッドから呼ばれるとは限りません（同時には呼ばれません）。ウィンドウ・COM のオブジェクト・スレッドに結びつく
  ライブラリのオブジェクトは、プラグインが自分で作ったスレッドの中で作り・使い・消してください（3-3）。
  - 例：DirectMusic・DirectShow・Media Foundation のオブジェクトを、本体から呼ばれたスレッドで作って別のメソッドで使うと、
    呼び手の COM の状態によっては開けないことがあります（本体以外のアプリから使われるときなど）。
- 決まり：メソッドを自分のスレッドへの指示にする場合、引数と結果は値で渡してください（呼び出し側の変数のアドレスを渡すと、
  待つのをやめた後でスレッドが書き、呼び出し側を壊します）。
- 決まり：指示の終わりを待つときは時間の上限を付け、終わらなければ「待ちますか」と聞くなどして、待つのをやめられるようにしてください。
  待つのをやめたら、以後は指示を送らず、GetStatus は KPI_STATUS_ERROR を返してください（本体が次の曲へ進めるように。
  単曲リピートで同じ曲を開き直して、また固まるのを防ぐ）。
  - 待つのをやめてスレッドを置いて先に進むときは、自分の DLL をプロセスが終わるまで外れないように固定してください
    （GetModuleHandleExW に GET_MODULE_HANDLE_EX_FLAG_FROM_ADDRESS | GET_MODULE_HANDLE_EX_FLAG_PIN。XP にもあります）。
    固まったスレッドを安全に終わらせる方法はなく、本体がプラグインを解放・再読み込みした後にそのスレッドが動くと、外れた DLL の
    コードを実行して落ちるためです。TerminateThread は使わないでください。
  - スレッドが終わらないまま参照カウントが 0 になったときは、スレッドと共有するもの（またはインスタンス自体）を、スレッドが
    終わったときにスレッドが消すようにしてください。
  - 待つのをやめて先に進む処理の中では、そのファイルの IKpiFile を呼ばないでください。IKpiFile のメソッド（GetFileName を含む）は、
    ほかのスレッドが同じ IKpiFile の Read の中にいる間は待たされることがあり、置いてきたスレッドが Read の中で止まっていると、
    一緒に止まります。ファイル名が要るなら、スレッドを始める前に写しておいてください。
  - 待つのをやめても、止まった処理はプロセスが終わるまで残ります（CPU やメモリを使い続けることがあります）。
    本体を起動し直すように、メッセージログで 1 回だけ知らせると親切です（8）。
- 決まり：自分のスレッドの中で待つときも、時間の上限を付け、待つ間もメッセージを処理してください（レンダラーなどが自分のスレッドの
  ウィンドウにメッセージを送って待つことがあり、止めると互いに待ち合います）。

### 7-4. 映像のウィンドウ

映像のウィンドウは、本体が作った親ウィンドウの中に描くか、プラグインが自分で作るかを選べます。
本体の親ウィンドウを使うと、位置・大きさ・全画面・常に手前に表示・右クリックのメニュー・ドラッグでの移動などを本体が行うので、
プラグインはそれらを作らなくて済みます（デコーダの映像と同じウィンドウです。6-15）。

- 本体の親ウィンドウを使う場合：
  - GetCaps で KPI_PLAYER_CAPS_VIDEO_PARENT を返してください（曲ごとに変えてかまいません。映像のない曲では返さない）。
    本体は、これがある場合だけ、Select の後・最初の Play の前に 1 度だけ CreateVideoWindow(親ウィンドウ, &子ウィンドウ) を呼びます。
    形と意味は、デコーダの IKpiVideoWindow::CreateVideoWindow と同じです（BOOL CreateVideoWindow(HWND hParent, HWND *phChild)。
    成功したら TRUE を返し、*phChild に子ウィンドウを入れる）。
  - 子ウィンドウの決まりは、デコーダの映像（6-15 の「本体の親ウィンドウの中に描く」）と同じです：隠したまま作る、WS_DISABLED・WS_EX_NOPARENTNOTIFY・
    WS_CLIPSIBLINGS を付ける、親ウィンドウへ SendMessage しない、自分のスレッドでメッセージを処理し続ける、WM_SIZE で映像を置き直す。
    先に作っておいた描画用のウィンドウ（WS_CHILD）を、CreateVideoWindow で SetParent して親ウィンドウの子にしてもかまいません
    （レンダラーを作り直さずに済みます）。タイトルの決め方（子ウィンドウにウィンドウ名を付けると、それがタイトルになる）も同じです。
  - 子ウィンドウは、IKpiPlayer を解放するまでに消してください。親ウィンドウは消さないでください（本体が曲をまたいで使います）。
  - 子ウィンドウを返したら、本体は SetVisible・GetWindowPosition・SetWindowPosition・SetTopMost を呼びません。Play の bVisible も使わなくてかまいません。
  - kbrunkpi.exe 経由のときは、kbrunkpi.exe が自分のプロセスに作った親ウィンドウが渡されます（プラグインから見れば同じです）。
  - 子ウィンドウを作れなかったら、*phChild を NULL にして FALSE を返してください。本体は、hParent を NULL にしてもう一度呼び、
    プラグインが自分のウィンドウを使うものとして扱います。hParent が NULL の呼び出しは「自分のウィンドウを使って」の意味で、
    *phChild を NULL にして TRUE を返します（することがなければ、それだけでかまいません）。
  - KPI_PLAYER_CAPS_VIDEO_PARENT を返さないプラグインには、今の本体は CreateVideoWindow を呼びません。その場合の実装は
    「*phChild を NULL にして、hParent が NULL なら TRUE、そうでなければ FALSE を返す」だけでかまいません。
  - デコーダの IKpiVideoWindow と違う点：最初の表示は Play の bVisible で決まります（デコーダは SetVisible(TRUE) まで出しません）。
    演奏プラグインのメソッドは同時に呼ばれません（デコーダのウィンドウの指示は、Seek・Render と同時に呼ばれることがあります）。
- 自分のウィンドウを使う場合：
  - Get/SetWindowPosition の左・上はウィンドウの左上（スクリーン座標）、幅・高さは映像（クライアント領域）の大きさで、枠を含みません。
    最大化・全画面のときは、元に戻したときのものです。枠の大きさは AdjustWindowRectEx で求めてください。
  - 本体は画面に収まるように直してから SetWindowPosition を呼びますが、それでもはみ出すときは、いちばん近いモニターの作業領域に
    収めてください（マルチモニタ）。
  - 閉じるボタンでは、ウィンドウを隠すだけにしてください（本体は次の Play・SetVisible でまた出します）。
  - GetCaps で、本体が位置を変えられるなら KPI_PLAYER_CAPS_WINDOW_MOVE、大きさを変えられるなら KPI_PLAYER_CAPS_WINDOW_SIZE を
    返してください（ふつうは両方）。返さないと、本体はそのウィンドウの位置・大きさを変えません。
    - 外部のアプリのウィンドウを使うなどで変えられない方があるなら、そのフラグを返さず、SetWindowPosition のその値は無視して
      かまいません。GetWindowPosition は、変えられない方も含めて実際の位置・大きさを返してください。大きさを変えられないなら、
      dwVideoWidth/dwVideoHeight にその大きさを入れてください（0 だと映像のない曲として扱われ、ウィンドウのメソッドは呼ばれません）。
    - 本体は、フラグのない方の値を次の曲に引き継ぐ位置・大きさとして覚えず、画面に収める計算には実際の値を使い、大きさを変えられない
      曲では「動画サイズ」のメニューを使えなくします。
  - SetVisible・SetTopMost に対応できない（従えない）なら、何もしなくてかまいません。本体は表示・常に手前の状態を取得しません。
  - 決まり：自分のスレッドでウィンドウを持ち、メソッドをそのスレッドへの指示で処理するなら、移動・大きさの変更・メニューのループの間も
    指示を処理してください。タイトルバーのドラッグなどの間は、Windows がそのスレッドの中で自分のループを回すので、プラグインの
    メッセージループが動かず、本体が待たされて止まります（約 50ms ごとに GetPosition が呼ばれるため）。
    WM_ENTERSIZEMOVE・WM_ENTERMENULOOP でタイマーを始めて WM_TIMER で指示を処理し、WM_EXITSIZEMOVE・WM_EXITMENULOOP で止めてください。
- 縦横比を保って映像を置くとき、EVR（DirectShow の EVR・Media Foundation の映像のレンダラー）には描画用のウィンドウ全体を
  SetVideoPosition で渡し、MFVideoARMode_PreservePicture と SetBorderColor（黒）で、置き方と余白を EVR に任せてください。
  縦横比を保って置いた範囲だけを渡すと、最大化などで大きく広げたときに、余白に絵が残ることがあります（VMR9・VMR7 では起きません）。

### 7-5. DirectShow・Media Foundation を使う場合

演奏プラグインを作り直したときに分かったことです（デコーダプラグインにも当てはまります）。

- Media Foundation（Media Session）：
  - イベントの受け取り役（IMFAsyncCallback）は、プレイヤーとは別の参照カウントを持つオブジェクトにし、プレイヤーを消す前に切り離してください。
  - 開始・一時停止・停止・閉じるは、それぞれの完了の知らせを別々に待ち、失敗の知らせ（状態が失敗のイベント）でも戻ってください。
  - 今の状態で受け付けられない操作（止まっている・最後まで再生した後の一時停止、一時停止していないときの再開など）は送らないでください。
    エラーで戻り、完了の知らせが来ないので、知らせを待つと固まります。
  - トポロジーにつながないストリームは DeselectStream してください。
  - 閉じるときは、Close → 閉じた知らせを待つ（上限付き） → メディアソースの Shutdown → Media Session の Shutdown → Release の順にしてください。
  - Windows Vista には MFCreateMFByteStreamOnStream がありません（Windows 7 から）。GetProcAddress で確かめてから使ってください。
- DirectShow：
  - グラフのイベントを待ち、EC_COMPLETE のほか、EC_ERRORABORT・EC_STREAM_ERROR_STOPPED（エラー）、EC_USERABORT も見てください。
    エラーの理由は lParam1 の HRESULT です。EC_USERABORT（映像のウィンドウを閉じたなど）はエラーではありません。
  - Run の前に、前の再生のイベントが残っていれば捨ててください（始めた直後に、前の EC_COMPLETE で止まったとみなさないように）。
  - 使いたいビデオレンダラーは、先にグラフに入れてから RenderFile・Render で組ませてください。
  - ウィンドウを持つレンダラー（古いレンダラー・madVR など）は、IVideoWindow で描画用のウィンドウの子にし、put_MessageDrain で
    クリック・キーをマウスの操作を受け取るウィンドウ（本体の親ウィンドウなど）に届けてください。
  - IKpiFile から開けない形式は、GetRealFileW の実ファイルから開き直すと開けることがあります（ストリームを受けられるスプリッタがない形式）。
- 著作権保護（DRM）されたファイル（DRM の .wmv など）：
  - Media Foundation は、Source Reader・保護しない Media Session では開けず、DRM 関係の HRESULT で失敗します
    （MF_E_DRM_UNSUPPORTED・MF_E_NO_CONTENT_PROTECTION_MANAGER など。mferror.h の 0xC00D3700・0xC00D3706・0xC00D7187 と、
    0xC00D7148〜0xC00D7159 のライセンス・保護関係）。
  - DirectShow は、DRM のファイルをエラーにせず、正しく再生できないまま演奏を進めてしまうことがあります。
  - 決まり：DS・MF の両方で開ける作りなら、MF が DRM 関係の HRESULT で失敗したときは DS を試さず、開けなかったことにしてください。
    理由はメッセージログで知らせると、利用者に分かります（8）。

### 7-6. 古い部品（ActiveX コントロールなど）やライブラリを使う場合

- MIDI を演奏プラグインで鳴らすとき、本体が渡すのは元のファイルではなく、本体が作り直した SMF（フォーマット 0）です。
  プラグインやライブラリの SMF の解析を確かめるときは、元のファイルを直接渡す形でも試してください。
- ActiveX コントロール（.ocx）は、レジストリに登録しなくても使えます。ocx を LoadLibraryEx（絶対パス）で読み、DllGetClassObject を直接呼んで
  クラスファクトリを得て、自前の最小のコンテナ（IOleClientSite・IOleInPlaceSite・IOleInPlaceFrame など）に置きます。
  CoCreateInstance を使う作り（MFC の CreateControl など）は、登録が要ります。
  - 古い ActiveX は STA でないと動かないことが多いので、STA のスレッドを自分で作って、その中で作り・使い・消してください（3-3・7-3）。
  - 大きさを変えるときは、SetObjectRects に加えて IOleObject::SetExtent も渡してください（渡さないと描く大きさが変わらない部品があります）。
- 部品が自分でメッセージボックスを出して止まることがあります（壊れたファイルを開いたときなど）。演奏プラグインの呼び出しに本体は時間の上限を
  設けていないので、出たままだと本体が待ち続けます。自分のスレッドに WH_CBT のフックを掛けて閉じ、その文を理由としてメッセージログに出す
  方法があります（8）。
- 決まり：実ファイルのパス（GetRealFileW/A）を部品やライブラリに渡すときは、相手がパスをどう解釈するかを確かめてください。
  パスを URL として扱う部品（%xx を文字に直すなど）では、名前しだいで別のファイルを開いてしまいます。そのような名前は、渡す前に断ってください。
