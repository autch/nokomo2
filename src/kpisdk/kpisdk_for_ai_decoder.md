# kpisdk の補足（AI 向け）：デコーダプラグイン

kpisdk_for_ai.md（入口）の続きです。先に入口の「読み方」と 0 節（設計の考え方）を読んでください。
節の番号は全ファイルを通した番号です（「6-1」はデコーダプラグインの 6 節の 1）。

## 6. デコーダプラグイン

### 6-1. IKpiFolder::OpenFile に渡す名前（安全面）

- 決まり：データの中に書かれた名前（参照ファイルの名前、プレイリストの中の名前など）を IKpiFolder::OpenFile に渡す前に、プラグインで検査してください。
  - IKpiFolder::OpenFile は、.. も絶対パスも UNC も開く仕様です（kpi.h の OpenFile の例 3・4・8）。本体が止めるのは LAN の外の UNC だけです（v3.17beta5 以降）。
  - 渡してよい名前の目安：
    - 相対パスだけにする。先頭が \ か / のもの（絶対パス・UNC・\\?\・\\.\）は拒否する。
    - : を含む名前は拒否する（ドライブの指定 C:\・C:name、代替データストリーム name:stream、URL）。
    - > を含む名前は拒否する（IKpiFolder の書き方では、アーカイブの中を指す）。
    - < " | ? * と制御文字（0x20 未満）を含む名前は拒否する。
    - 末尾が . か空白の要素は拒否する（Windows が取り除くので、別の名前として開かれる。"..." など）。
    - デバイス名（CON・PRN・AUX・NUL・CONIN$・CONOUT$・COM0〜9・LPT0〜9・上付き数字の COM¹ など。
      最初の . より前を、後ろの空白を除いて大文字・小文字を区別せずに比べる）は、どの階層の要素でも拒否する。
    - .. は、形式の仕様で親のフォルダを参照する必要があるときだけ許す。必要がなければ拒否する。
    - 区切りは \ にそろえ、. と途中の .. を取り除いてから渡す。
  - 参照の中でさらに参照できる形式（自分自身を参照できるものを含む）では、開く深さと、1 曲を開く間に開くファイルの総数に上限を設けてください
    （値はプラグインが形式に合わせて決めます。例：深さ 8、総数 4096）。自分自身の参照は深さで、参照が指数的に増えるものは総数で止まります。
- 決まり：再生するファイル自身をもう一度開くときは、IKpiFolder::OpenFile(GetFileName の名前) ではなく IKpiFile::CreateClone を使ってください。
  - 理由：GetFileName の名前と実体の名前が違うことがあります（kpi.h の GetRealFile の説明）。同じ名前を渡しても同じものが開ける保証はありません。

### 6-2. ループタグ（loopstart・looplength）で本体にループさせる

kpisdk には書かれていませんが、本体には「タグで渡したループの位置で本体がループさせ、後奏まで再生する」仕組みがあります。

- 渡し方：Select で pTagInfo が NULL でなく、dwTagGetFlags に KPI_TAGGET_FLAG_GENERAL があるときに、
  `wSetValueW(L"loopstart", -1, 値, -1)`・`wSetValueW(L"looplength", -1, 値, -1)` を呼びます。値はサンプル単位の 10 進の文字列です。
  - 名前の大文字・小文字は区別されません。looplength がない・負のときは「loopstart から曲の終わりまで」になります。
  - 再生のための Select では、本体は dwTagGetFlags に KPI_TAGGET_FLAG_ALL を渡します。
  - GetTagInfo を呼ばなければ、本体は Select の後でいつもどおり既定のタグ取得もします（6-6）。
- プラグインがすること：「ループしない曲」として返します（KPI_MEDIAINFO の qwLoop = 0、qwLength = ファイルの最後までの長さ）。
  デコードもファイルの最後まで普通に行い、自分ではループしません。Seek はサンプル単位で正確に行ってください。
- 本体の動き：
  - ループタグがあれば、qwLoop より優先してこの仕組みを使います。
  - loopstart + looplength まで来たら loopstart へ Seek して繰り返します。設定の回数の後、後奏（ループの終わりからファイルの終わりまで）が
    本体の設定より長ければ最後まで再生し、短ければループに戻ってフェードアウトします。
    （v3.17beta5 より前の本体は、後奏の判定に誤りがあり、後奏が鳴りませんでした）
  - ループが 100ms 以下、または本体の設定の長さ以下かつ曲の長さの 1/8 以下なら、ループタグを無視します（楽器の 1 音の録音に付いている短いループなどが外れる）。
    loopstart が曲の長さ以上のものや、終わりの位置があふれるものも無視します。
  - CueSheet の曲の再生では pTagInfo が NULL なので、ループタグは渡りません。
- qwLoop（KPI_MEDIAINFO）で伝える方式との使い分け：
  - qwLoop の方式：プラグイン（ライブラリ）が自分でループの終わりから始まりへ戻ってデコードし続けます。継ぎ目はライブラリがつなぐので、
    ループの位置で状態を保存して戻れるライブラリなら、継ぎ目なく正確です。後奏は鳴りません。Render は常に要求どおりの数を返します。
  - ループタグの方式：本体が Seek で戻るので、Seek が正確で、ループの始まりへのシークが十分速い形式に向きます。後奏を本体の設定どおりに扱えます。
    シークのたびに先頭からデコードし直すライブラリでは、ループのたびに負荷がかかります。
  - ファイルに LOOPSTART・LOOPLENGTH のタグ（Ogg Vorbis のコメントなど）がある場合は、それをそのまま通知すればこの仕組みが働きます。
  - 形式固有のループの情報（WAV の smpl チャンクなど）は、ループタグに変換して渡せます。smpl の終わりの位置はループに含まれるので、
    looplength = 終わり − 始め + 1 です。

### 6-3. プラグインが使う DLL の置き場所と読み込み方

- 本体の動き：
  - 本体と kbrunkpi.exe は、起動直後に SetDllDirectory(L"") でカレントフォルダを DLL の検索対象から外しています。
  - プラグインを読み込む間だけ、SetDllDirectory でプラグインのフォルダを検索対象にし、読み込みが終わると L"" に戻します。
- 決まり（DLL はプラグインと同じフォルダに置く）：
  - プラグインが普通に（静的に）リンクした DLL：プラグインの読み込み時に、プラグインのフォルダから見つかります。追加の作業は要りません。
  - 後から名前だけで LoadLibrary する DLL（遅延読み込み /DELAYLOAD を含む）：そのときにはプラグインのフォルダは検索対象ではないので、
    名前だけでは見つかりません（PATH にある同じ名前の DLL が読まれるおそれもあります）。プラグインのフォルダの絶対パスで読んでください。
    - プラグインのフォルダは、GetModuleHandleEx（GET_MODULE_HANDLE_EX_FLAG_FROM_ADDRESS）と GetModuleFileName で求められます。
    - 読み込む DLL が別の DLL を名前だけで参照するなら、LoadLibraryEx(絶対パス, NULL, LOAD_WITH_ALTERED_SEARCH_PATH) で読むか、
      依存される側から順に絶対パスで読んでおきます（読み込み済みの同じ名前のものが使われます）。
    - 遅延読み込みでは、同じ名前の DLL がほかの場所から先に読み込まれていると、そちらに結び付きます。
      遅延読み込みの通知の関数（__pfnDliNotifyHook2 の dliNotePreLoadLibrary）で、自分で読み込んだハンドルを返すと確実です。
    - DLL がないときに、遅延読み込みの関数を読み込み済みかを確かめずに呼ぶと落ちます。呼ぶ経路の入口で必ず確かめてください。
      DLL がなくても、それを使わない形式は再生できるようにしておくと親切です。

### 6-4. 本体が受け付ける形式（KPI_MEDIAINFO）

本体は、Select でプラグインが返した KPI_MEDIAINFO を確かめ、次に合わなければその曲を再生しません（落ちはしません）。
チャンネル数とビット数は仕様（kpi_decoder.h）のとおりです。再生周波数の範囲と dwUnitSample の上限は、今の本体の都合の制限です（0 を参照）。

- dwNumber が要求した曲番号と同じで、dwCount 以下であること。
- dwSampleRate が 4000〜4194304 Hz であること（今の本体の制限。通常のデータ・古い形式の 5512Hz など・DSD を PCM に包んだものまで通る範囲）。
- dwChannels が 1〜8 であること（7.1ch まで。v3.17beta6 以降。v3.17beta5 以前の本体は 1 か 2 だけを受け付け、3ch 以上の曲は再生できません）。
- nBitsPerSample が 8・16・24・32・-32・-64 のどれかであること。
  - 8bit は符号なし（WAV と同じ。無音は 0x80）です。16bit 以上の整数は符号付きです。
- dwUnitSample が 65536*4 以下であること（今の本体の制限）。
  - プラグインの決まりは kpi_decoder.h のとおり 16384 以下です。本体はそれより大きな値も念のため 65536*4 まで受け付けます。

決まり：

- 3ch 以上のデータは、チャンネル数のまま返し、dwSpeakerConfig にスピーカーの配置を入れてください（kpi_decoder.h）。
  - 配置が分からなければ 0 にしてください（チャンネル数で決まる標準の配置。kpi_decoder.h の表）。
  - データは、配置のビットの小さい順（WAV と同じ順）に並べてください。形式によって並びが違う（Vorbis・Opus・AAC など）ときは、
    プラグインで並べ替えてください。WAV・FLAC は標準の配置と同じ並びです。
  - 本体は、立っているビットの数が dwChannels と合わない値と、定義のないビット（SPEAKER_TOP_BACK_RIGHT（0x20000）より上。SPEAKER_ALL など）を
    含む値を、0 として扱います。ほかのアプリから使われたときのために、プラグインでも同じように確かめておくと安全です。
  - 1ch・2ch でも dwSpeakerConfig を入れてかまいません（0x4・0x3 など）。
- 9ch 以上のデータは本体が受け付けないので、プラグインで 8ch 以下（たとえば 2ch）にまとめるか、Open で失敗させてください。
- 要求（cpRequest）の dwChannels は見なくてかまいません（本体は 0 を入れています）。3ch 以上を返すかは、要求と関係なく決めてかまいません。
  - v3.17beta5 以前の本体でも使えるように、2ch にまとめるかをプラグインの設定で選べるようにしてもかまいません（既定はまとめない）。
- 出力デバイスが 3ch 以上に対応していないときや、利用者が設定でそう選んだときは、本体がステレオにまとめて出力します。
  プラグインがまとめる必要はありません。
  - DSD（FORMAT_DOP）の 3ch 以上は本体がまとめられないので、出力デバイスが対応していなければ再生できません。
- 曲の間を途切れずにつなぐ（ギャップレス）のは、3ch 以上なら、前後の曲のチャンネル数と配置が同じときだけです。
- まとめられない・本体が受け付けない形式のデータは、Open で失敗させてください。開いた後の Select で本体に断られるより、
  ほかの方法（同じプラグインの中の別の処理など）に回せる分よくなります。

### 6-5. 1 ファイル複数曲

- 本体の動き：
  - 演奏リストへの追加：1 ファイル複数曲の拡張子（cszMultiSongExts。曲番号の指定なし）のファイルは、追加のときにその場で（メインスレッドで）開いて曲数を得て、
    1 曲ずつ Select(n, NULL, pTagInfo, フラグ) でタグを取り、曲ごとの項目にします。
    プラグインから見ると「Open(cpRequest = NULL) を 1 回、Select(n, ppMediaInfo = NULL) を曲の数だけ」です。
    複数曲でない拡張子は、追加のときには開かず、タイトルは後で読みます。
  - Media エクスプローラ：1 ファイル複数曲の拡張子のファイルは、本体の設定によって「フォルダのような項目」として並び、中を開くと同じく全曲のタグを取ります。
  - 今の本体は、1 ファイルの曲数を 9999 曲までにしています（本体の都合の制限。0 を参照）。プラグインが返した曲数がそれより多くても、
    9999 曲までしか並びません。プラグインは本当の曲数を返してかまいません。
  - Select の曲番号：Open が返した曲数より大きい曲番号は渡されません（v3.17beta5 以降。それより前の本体はタグ取得のときに渡すことがあったので、
    古い本体でも使う場合は、プラグインで範囲を確かめないと落ちることがあります）。
- 決まり（目安）：
  - cszMultiSongExts に入れた拡張子のファイルは、演奏リストに追加しただけで開かれ、全曲の Select が呼ばれます。
    複数曲になる見込みが低い拡張子は入れない方が、追加が速くなります。
  - 曲が多いファイルでは、タグ取得用の Select（ppMediaInfo == NULL）を軽くしてください（曲の解析を最小限にする。毎回ファイルを開き直さない）。
  - 曲番号・曲数を、トラック番号のタグ（TrackNumber・TrackTotal）として渡さないでください。曲番号と曲数は本体がもともと知っています
    （Select の番号と Open が返した曲数）。ファイルの中にトラック番号の情報がある場合は、それを渡してかまいません。
  - cszMultiSongExts に拡張子を入れるプラグインは、dwSupportTagInfo の TAG_TITLE の有無にかかわらず、cpRequest == NULL の Open と
    ppMediaInfo == NULL の Select に対応してください（6-8）。

### 6-6. タグ

- タグの名前の比較は、大文字・小文字を区別しません（"title" と "Title" は同じ）。定義済みの名前は kmp_pi.h の SZ_KMP_NAME_XXX を参照してください。
- 本体の拡張子による既定のタグ取得を使わないなら、Select の中で GetTagInfo(…, KPI_TAGTYPE_NONE, 0) を呼びます（kpi.h のとおり）。
  - 逆に、プラグインが wSetValueW などで値を渡しても、GetTagInfo を呼ばなければ既定のタグ取得は止まりません。
    「本体にいつものタグを読ませつつ、プラグインの情報を足す」ときは、GetTagInfo を呼ばずに値だけを渡してください。
- 本体のドキュメント部（曲の情報の表示）は、曲の情報の名前と値をすべて「名前: 値」の形で並べます（定義済みでない名前は < > で囲みます。
  値に改行があれば改行して表示します）。プラグイン独自の情報（形式・コーデック・ループの位置・マーカーなど）を見せたいときは、Select で渡すだけで表示されます。
  - 同梱のプラグインは、独自の情報の名前を英語にしています（Format・Codec など）。
  - 値の改行は CR+LF にそろえてください。0 や空の値は渡さない方が見やすくなります。
- 文字コード：wSetValueA は値を ANSI（日本語の環境では Shift_JIS）としてしか変換しません（UTF-8 かどうかの判別はしません）。
  UTF-8 のことがある文字列は、wSetValueU8 を使うか、プラグインで判別して wSetValueW で渡してください。
  - 本体の wSetValueU8 は、UTF-8 として正しくなければ ANSI として読み直します（kbrunkpi.exe 経由のときも同じです）。
    データの中の文字コードが分からない文字列は、wSetValueU8 で渡せば、本体では UTF-8 でも Shift_JIS でも文字化けしません。
  - 本体以外のアプリ（6-9）は、読み直すとは限りません。どのアプリでも化けないようにするなら、プラグインで判別して wSetValueW で渡してください。
- 本体が Select に渡す dwTagGetFlags：
  - 再生のための Select は KPI_TAGGET_FLAG_ALL です（GENERAL も入ります）。
  - 演奏リストへの追加や Media エクスプローラの情報集めは、TITLE・ARTIST・COPYRIGHT だけです（GENERAL は求めません）。
  - 決まり（目安）：時間のかかる情報（ファイルを調べ直す計算、長い説明文など）は、KPI_TAGGET_FLAG_GENERAL があるときだけ作ってください。
    1 ファイル複数曲の何千曲もの情報集めでは作られず、再生する 1 曲でだけ作られるようになります。
- dwSupportTagInfo に TAG_TITLE を立てると、Media エクスプローラで項目が画面に表示されるときに、1 項目ずつ（cpRequest == NULL で）Open・Select されます。
  これはメインスレッドで動くので、Open が重いとその間 Media エクスプローラの表示やスクロールが止まります。
  - 決まり（目安）：TAG_TITLE を立てるなら、タグ取得用の Open（cpRequest == NULL）は、ヘッダの解析など必要最小限にしてください
    （kpi_decoder.h にも「ファイルオープンの処理を最小限に抑えること」とあります）。
  - TAG_TITLE がなければ、Media エクスプローラのタイトル取得ではプラグインは開かれません（ただし 6-5・6-8 の例外があります）。
- dwSupportTagInfo の TAG_EXTRA は、今の本体ではプラグイン設定の表示にしか使いません。TAG_DECODER_EXCLUSIVE は未実装で、本体は見ていません（kpi_decoder.h）。

### 6-7. 1 つのインスタンスのメソッドが呼ばれるスレッド

本体の中で動かす場合、1 つのインスタンスのメソッドは別々のスレッドから呼ばれますが、同時には呼ばれません。

- Open・Select（曲の切り替え）はメインスレッドから呼ばれます。曲の切り替えの Select は、デコードが終わっていることを本体が確かめてから呼びます。
- Render はデコード用のスレッドから呼ばれます。
- Seek は、場面によって呼ばれるスレッドが違います（どの場合も、Render と同時にはなりません）。
  - 曲を開いた・選んだ後の最初の Seek（演奏を始める前や、ギャップレスで次の曲に備えるとき）は、メインスレッドから呼ばれます。
  - 再生中のシークは、再生用のスレッドから、デコード用のスレッドの今の Render が終わるのを待ってから呼ばれます。
  - ループタグ（6-2）で本体がループさせるときの Seek と、単曲リピートで先頭に戻る Seek は、デコード用のスレッドから呼ばれます。
- Seek の dwFlag（精度）は、本体が場面で変えて渡します（v3.17beta7 以降。それより前の本体は常に SEEK_FLAGS_SAMPLE）。
  - SEEK_FLAGS_SAMPLE：CueSheet の曲、ループの始めへの戻り、位置 0 へのシーク、曲を開いた後の最初の Seek など、正確な位置が要るとき。
  - SEEK_FLAGS_ACCURATE：利用者のシークで、歌詞・WRD・映像のある曲（本体は戻り値を表示の位置に使うので、戻り値が実際の音の位置と合っている必要があります）。
  - SEEK_FLAGS_ROUGH：利用者のシークで、それ以外の曲（速さ優先）。
  - 精度で速さが変わらないなら、dwFlag を見ずに、いつもできる限りの精度でシークしてかまいません（今のプラグインはどれもそうしています）。
    精度で速さが大きく変わる形式（索引のない可変ビットレートなど）だけ、dwFlag に応じて速い方法を選ぶ意味があります。
- UpdateConfig は、次の Seek・Render の直前に同じスレッドで呼ばれます。Render の最中に別のスレッドから呼ばれることはありません。
- IKpiVideoWindow に対応した場合だけ、例外があります（6-15）。そのうち SetVisible・SetTopMost・GetWindowPosition・SetWindowPosition は、
  メインスレッドから、Seek・Render の最中にも呼ばれます（GetCaps・SetPlayStatus・CreateVideoWindow は、Select と同じくメインスレッドから、
  Seek・Render と同時にならないように呼ばれます）。
- したがって、1 つのインスタンスの中では排他は要りませんが、スレッドに結びついたもの（TLS、COM のオブジェクト、スレッドごとの状態）は使わないでください（3-3）。
- kbrunkpi.exe 経由のときは、インスタンスごとに kbrunkpi.exe が 1 つ起動し、Open・Select・Seek・Render・UpdateConfig は、
  すべてその中の同じ 1 つのスレッドから、順に呼ばれます。本体の中で動かすときより制約が強いだけなので、上の決まりのとおりに作れば問題ありません。
  設定画面（ApplyConfig）は別のスレッドから呼ばれます（2-3）。

### 6-8. 1 ファイル複数曲のタグ取得（TAG_TITLE がなくても開かれる・曲番号 0）

- TAG_TITLE を立てていないプラグインも、1 ファイル複数曲の拡張子のファイルはタグ取得用に開かれます（2026-11 に kpi_decoder.h・kpi_player.h で明記）。
  - 1 ファイル 1 曲の拡張子：TAG_TITLE がないとき（dwSupportTagInfo = 0 も）は、タイトル取得にプラグインは使われません（Open が呼ばれない）。
  - 1 ファイル複数曲の拡張子（cszMultiSongExts）：dwSupportTagInfo の値に関わらず、演奏リストへの追加と、Media エクスプローラで
    その項目を開いたときに、Open(cpRequest = NULL) と全曲の Select(n, ppMediaInfo = NULL) が呼ばれます（6-5）。
    ファイルに含まれる曲の数を知る手段が Open の戻り値しかないためです。
  - 決まり：cszMultiSongExts に拡張子を入れるプラグインは、TAG_TITLE の有無にかかわらず、
    cpRequest == NULL の Open と ppMediaInfo == NULL の Select に対応してください。
    タイトル取得に対応しないなら、Select では何も通知せずに dwNumber を返すだけでかまいません。
- 曲番号 0 の Select（2026-11 に kpi_decoder.h で明記）：
  - 本体が曲番号 0 を渡すのは、1 ファイル複数曲の拡張子のファイル全体のタグ取得（Select(0, NULL, …)）だけです。1 ファイル 1 曲なら常に 1 です。
  - 戻り値：成功したら dwNumber と同じ値、失敗したら dwNumber と異なる値を返します。曲番号 0 の失敗は 0xFFFFFFFF にしてください
    （本体は「戻り値が要求した番号と同じなら成功」とみなすので、0 を返すと成功の扱いになります）。
  - 曲番号 0 で失敗を返すと、本体はそのファイルを開けないものとして扱います（書庫の中のファイルを演奏リストに追加しないなど）。
    ファイル全体のタグがないだけなら、失敗にせず 0 を返してください。

### 6-9. 本体以外のアプリから使われる場合

- kpi_CreateInstance の第 3 引数（IKpiUnknown）が NULL になりうるかは決まっていません（本体は NULL を渡しません）。使うプラグインは NULL を確かめてください。
  kpi.cpp の kpi_CreateConfig は NULL でも落ちません（常に既定値を返す IKpiConfig を返します）。
- IKpiDecoderModule::Open が失敗したときは、*ppDecoder を NULL にしてください。本体のヘルパー（kpi_CreateDecoder など）は呼ぶ前に NULL にしていますが、
  ほかのアプリがそうしているとは限りません。

### 6-10. 本体の再生位置を得る（古い非公式の仕組み）

ヘッダには書いていない、本体の非公式の機能です。デコーダプラグインが「いま聞こえている位置」と再生状態を知るために使えます。
kbmsxplug が使っています（ソースを公開しています）。旧仕様のプラグイン（kmp_pi.h）でも使えます。

v3.17beta7 からは、正式な口として IKpiVideoWindow（6-15）があります。新しく作るなら、そちらを使ってください
（映像・ウィンドウを出さず、再生位置だけが要る場合にも使えます）。この仕組みは、古い本体でも再生位置が要る場合と、旧仕様のプラグインの
ために残しています。IKpiVideoWindow に対応したデコーダには、本体はこの共有メモリを開きません（両方を用意してもかまいません。新しい本体では
IKpiVideoWindow の方だけが使われます）。

- 決まり：
  - IKpiDecoderModule::Open から戻るまでに、次の名前で名前付きの共有メモリを作り（CreateFileMapping(INVALID_HANDLE_VALUE, NULL, PAGE_READWRITE, 0, 16, 名前)）、
    MapViewOfFile してください。Select の時点で作るのでは遅すぎます（本体は Open の直後に開きに来ます）。
  - 名前：`kmp_status_filemapping_<プロセス ID>_<プラグインの HINSTANCE>_<IKpiDecoder のポインタ>`（すべて 10 進）。
    64bit 版は `L"kmp_status_filemapping_%lu_%llu_%llu"`、32bit 版は `L"kmp_status_filemapping_%lu_%lu_%lu"` で作ります。
    旧仕様のプラグインは、IKpiDecoder のポインタの代わりに HKMP を使います。
  - 中身は DWORD が 4 つ（16 バイト）です。

    ```c
    struct KMP_STATUS {
        DWORD dwStructSize; //プラグインが 16 を入れる
        DWORD dwAccepted;   //プラグインが 0 にしておく。本体が受け入れたら 1 になる
        DWORD dwPosition;   //本体が書く。いま聞こえている位置(ms)
        DWORD dwStatus;     //本体が書く。KPI_STATUS_STOP/PLAYING/PAUSE(kpi_player.h)
    };
    ```

  - dwStructSize が 16 以外なら、本体は使いません。
  - dwAccepted が 1 にならなければ（古い本体、ほかのアプリなど）、この仕組みは使えません。使えないときの動き方も用意してください。
- 本体の動き・使い方の注意は、IKpiVideoWindow の再生位置（6-15 の「再生位置・再生状態」）と同じです（書く値・更新の間隔・ギャップレスでの切り替わり）。
  - kbrunkpi.exe 経由のときも使えます。kbrunkpi.exe の中で同じ作り方の名前（kbrunkpi.exe のプロセス ID など）を作って本体に渡すので、
    プラグインは本体の中で動くときと同じ作り方でかまいません。

### 6-11. qwLength は出す音の位置で数える（qwLoop の方式で、位置をずらすプラグインだけ）

対象：qwLoop の方式（プラグイン自身がループする）で、先頭に無音を足す・先頭を捨てるなど、Render で出す音とファイルの中の位置を
ずらしているプラグインだけの話です。ループタグの方式（6-2。qwLoop = 0・qwLength = ファイルの最後までの長さ）や、
位置をずらさないプラグインには関係ありません。

- 本体の動き：ループ曲の総時間は qwLength + (ループ回数 − 1) × qwLoop + qwFadeOut で求めます。表示する長さと、
  フェードアウトを始めて演奏を終える位置は、この値で決まります。qwLength − qwLoop（前奏の長さ）は使いません。
- 決まり：qwLength は「出す音の先頭から、最初にループの終わりに着くまで」を、実際に Render で返す音の位置で数えてください。
  ファイルの中のループの終わりの位置をそのまま使わず、足した分・捨てた分を足し引きしてください。
  - 例：ファイルの中でループの終わりが 30 秒の曲で、先頭に 2 秒の無音を足して出すなら、qwLength は 32 秒です。
    30 秒にすると、表示の長さと演奏を終える位置が 2 秒ずれます。
  - Seek で渡される位置も、出す音の位置です。
  - 先頭を捨ててループの途中から出す場合は、qwLength < qwLoop になってかまいません（1 回目のループが途中から始まるだけです）。
- 確かめ方：サンプルごとに値の違うデータ（位置が分かるデータ）をデコードして、出す音の値が飛ぶ位置（ループの継ぎ目）が qwLength と
  一致するかを見てください。継ぎ目のない正弦波などでは、ずれていても分かりません。

### 6-12. 壊れたデータでも Render・Seek・Select が戻ってくるようにする

- 本体の動き：本体の中で動いているとき、本体は Render・Seek・Select が戻るのを期限なしで待ちます。戻らないと本体が固まります。
  kbrunkpi.exe 経由のときは、5 秒たっても戻らなければ、強制終了するかを尋ねるダイアログが出ます（固まった後の逃げ道で、固まらないようにするものではありません）。
  本体はデータの中身を解釈しないので、本体の検査ではこれを防げません。
- 決まり（プラグインのコードでできること）：
  - ライブラリのデコードの関数を呼ぶプラグインのループには、進まないとき（成功が返るのに出力が 0 のまま、など）に抜ける仕組みを入れてください
    （例：空の結果が一定の回数続いたら曲の終わりとみなす）。ループはプラグインのコードなので、必ず抜けられるようにできます。
  - ライブラリに渡すと止まる・極端に時間がかかると分かっている値（データから来る負の長さ、曲の長さを大きく超える切り捨てなど）は、
    渡す前に弾くか、曲の長さ程度に収めてください。1 回の呼び出しの時間も、kbrunkpi.exe の 5 秒に正常な処理で引っかからない程度に抑えてください。
- 目安（できる範囲で）：ライブラリや OS の部品（Media Foundation など）の中で止まるものは、プラグインからは直せません。
  - ライブラリを直せるなら直してください。直せなければ、気づいた範囲で、止まる値を渡す前に弾く程度でかまいません。
  - 専用のスレッドで呼んで、時間切れで見切る逃げ方もありますが、手間が大きく、止まったスレッドは残ったままになります。必須ではありません。
    使う場合は、時間切れの後にその部品に触らないこと、止まったスレッドが後で戻ってきても落ちないようにプラグインの DLL を解放させないこと
    （GetModuleHandleEx の GET_MODULE_HANDLE_EX_FLAG_PIN。XP にもあります）に気をつけてください。

### 6-13. dwPluginVersion は、同じ拡張子のプラグインの間の優先度にも使われる

- 本体の動き：同じ拡張子に対応するプラグインが複数あるとき、dwPluginVersion の大きい方を優先して使います。同じ値ならプラグインのファイル名の順です。
  kpi_decoder.h には「プラグインのバージョン」とだけ書かれていて、優先度に使われることは書かれていません。
- 目安：
  - 対応する拡張子が非常に多いプラグイン（ゲーム音楽の形式をまとめて扱うものなど）は、ほかのプラグインの邪魔をしないよう、低い値（0）にしてください。
  - 優先度を利用者が変えられるようにするなら、真偽値の設定にして、true のときに最大（0x7FFFFFFF）にする形が使えます
    （KbMedia の同梱のプラグインは HighPriority という名前にそろえています）。設定を変えたら、ApplyConfig で KPI_CFGRET_RELOAD_KPI を返して、
    本体にプラグインの情報を読み直させてください。

### 6-14. ほかのデコーダプラグインを使う（kpi_CreateDecoder）

デコーダプラグインの中から、ほかのデコーダプラグインで別のファイルをデコードするときの話です（参照するファイルを鳴らす形式など）。

- 本体の中で動いているときは使えます。kbrunkpi.exe 経由のときだけ失敗します（kpi.h・5）。
  古い kpi.h の説明には「現在未実装」とありますが、kbrunkpi.exe 経由のときだけの話です。呼ぶ側のプラグインは、kbrunkpi.exe 経由にならないように dwMultipleInstance を
  KPI_MULTINST_INFINITE にしてください（KPI_MULTINST_ZERO では常に失敗します）。
- 本体の動き（使うプラグインの選び方）：渡した IKpiFile の GetFileName の拡張子で、本体が選びます。中身は見ません。
  - 同じ拡張子のプラグインが複数あるときは、優先度（6-13）がいちばん高いものを 1 つだけ使います。その Open が失敗しても、ほかのプラグインは試しません。
  - 選ばれたのが呼んだプラグイン自身なら、失敗します。
  - 選ばれたのが、今その呼び出しの入れ子の途中にいるプラグイン（A が B を使い、B がまた A を使う場合の A）なら、失敗します（v3.17beta7 以降）。
    本体は、kpi_CreateDecoder で開いたデコーダの Open・Select・Seek・Render の間、呼んだプラグインを覚えておき、同じプラグインが 2 度入れ子にならないようにします。
  - 拡張子 .mid のファイルは、本体の MIDI の設定に従って本体が処理してから、デコーダに渡します。
- 決まり：データの中の名前で開くファイルを決めるときは、自分が対応する拡張子のファイルは開かないでください。
  - 理由：自分自身や、別のプラグインを経由して戻ってくる循環（A が B を使い、B が A を使う）は、v3.17beta7 以降の本体では失敗になって止まりますが、
    それより前の本体（循環は止まらない）や、本体以外のアプリでは止まらないことがあります。開く前に除いておけば、どの環境でも止まります。
  - 6-1 の名前の検査と、深さ・総数の上限も同じように必要です。
- 本体の動き（使われる側のインスタンスの数）：使われる側のプラグインの dwMultipleInstance は、本体が直接開くときと同じに数えます。
  - 本体の中で作れる数を超えたとき、KPI_MULTINST_ZERO のとき、利用者が別プロセスで使う設定にしたときは、kbrunkpi.exe 経由のデコーダが返ります。
    呼ぶ側からは区別なく使えます。
  - KPI_MULTINST_UNIQUE で使用中のときは失敗します。
- 本体の動き（返るデコーダ）：cpRequest の nBitsPerSample が 0 でなければ、そのビット数に変換して返します（変換できないビット数のときは Select が失敗します）。
- 決まり：返ったデコーダは、本体がデコーダを呼ぶときと同じ決まり（kpi_decoder.h）で呼んでください。
  - Render・Seek の前に Select を呼び、Select の後、最初の Render の前に Seek を呼ぶ。Select が失敗したら Render・Seek を呼ばない。
  - Select の曲番号は 1 から、Open が返した曲数まで。
  - KPI_MEDIAINFO::dwUnitSample が 0 でなければ、Render にはその数を渡す（要求された長さとの差は、呼ぶ側のバッファで調整する）。
  - *ppMediaInfo は次に呼ぶまでしか有効でないので、必要な値は写しておく。
  - cpRequest を NULL にして（タグ取得用に）開いたものは、Render・Seek しない。
  - Seek は要求より手前に戻ることがあるので、戻り値の位置を確かめる。
  - 返ったデコーダの Open・Select は自分の Open・Select の中で、Render・Seek は自分の Render・Seek の中で呼ぶ。
    こうすると、使われる側が呼ばれるスレッドが、本体から直接呼ばれるときと同じになります（6-7）。
  - 自分のロックを持ったまま kpi_CreateDecoder を呼ばない（3-1）。
- Select の pTagInfo：使われる側のタグが要らなければ NULL でかまいません。
  - 自分で実装した IKpiTagInfo を渡す場合、GetTagInfo（本体のタグ取得）は、自分の Select で本体から受け取った pTagInfo の GetTagInfo に
    そのまま渡してください（本体の pTagInfo が使えるのは、自分の Select から戻るまでです。NULL なら失敗を返します）。
  - 使われる側が GetTagInfo を呼ばなかったとき、本体なら Select の後に拡張子による既定のタグ取得をしますが、自分で実装した IKpiTagInfo ではその分は起きません。

### 6-15. 映像・ウィンドウ・再生位置（IKpiVideoWindow）

デコーダプラグインが、音に合わせて映像やウィンドウを出すための口です（kpi_video_window.h。v3.17beta7 から。対応は任意）。
IKpiDecoder の QueryInterface で IID_IKpiVideoWindow に答えると、本体が使います。できることは 3 つで、使うものだけ GetCaps で返します。

| GetCaps のフラグ | できること | 使っているプラグイン |
|---|---|---|
| VIDEO_PARENT | 本体が作った親ウィンドウの中に、映像を描く子ウィンドウを作る | kbdshow（動画）・kbbms（BGA） |
| WINDOW（＋WINDOW_MOVE・WINDOW_SIZE） | 自分のウィンドウ（外部のアプリのウィンドウを含む）を、本体の指示に従わせる | kbzmdrive（ZMDRIVE.exe のウィンドウ） |
| PLAY_STATUS | 本体の再生位置・再生状態を読む | kbdshow・kbbms |

どれもソースを公開しています。メソッドの説明は kpi_video_window.h にあります。ここでは、本体の動きと、作るときに気をつける点を書きます。

- 本体の呼び方：
  - Open → （QueryInterface） → Select → GetCaps → （SetPlayStatus） → （CreateVideoWindow） → Seek → Render …
  - QueryInterface は、対応しているかを確かめるだけの目的で呼ばれます（本体は Open の直後に呼びます）。答えただけでは何も始めないでください。
  - GetCaps は Select のたびに呼ばれます。SetPlayStatus と CreateVideoWindow は、1 つのインスタンスに 1 度だけです
    （1 ファイル複数曲では、そのフラグが初めて返った Select の後）。
  - CreateVideoWindow が「これから表示を始めるので準備して」の合図です。呼ばれなければ、ウィンドウを表示しないでください。
    本体は、演奏するために開いたときだけ呼びます。タグの取得や曲の長さの計算などで開いたとき、IKpiVideoWindow に対応していない本体、
    本体以外のアプリでは呼ばれません。
  - VIDEO_PARENT と WINDOW の両方を返すと、本体は先に親ウィンドウを渡して呼び、FALSE が返ったら NULL でもう一度呼びます。
  - どちらも失敗したら、本体は映像のない曲として演奏します。
- 呼ばれるスレッド（6-7）：
  - GetCaps・SetPlayStatus・CreateVideoWindow は、Select と同じスレッドから、その曲の最初の Seek の前に呼ばれます。Seek・Render とは同時になりません。
  - SetVisible・SetTopMost・GetWindowPosition・SetWindowPosition は、メインスレッドから、デコード用のスレッドの Seek・Render の最中にも呼ばれます。
    すぐに戻ってください。Seek・Render の終わりを待ってはいけません。停止中・一時停止中（Render が呼ばれていない間）にも呼ばれます
    （本体の「停止時に隠す」など）。
  - kbrunkpi.exe 経由のときは、ウィンドウの指示も同じ 1 つのスレッドから、Seek・Render の合間に呼ばれます。本体の中で動くときより
    制約が強いだけなので、上の決まりのとおりに作れば、どちらでも動きます。Seek・Render が長くかかる間は、指示の実行も遅れます。
    同じ指示が続けて出されたときは、最後のものだけが実行されることがあります。GetWindowPosition は、本体には少し前の値が返ります。
- QueryInterface の書き方：
  - IKpiDecoder と IKpiVideoWindow の両方を 1 つのクラスで実装する場合は、kpi_impl.h の `KbKpiUnknownImpl2` から派生させてください。
    QueryInterface がどちらにも答え、参照カウントは共通になります。

    ```cpp
    class MyDecoder : public KbKpiUnknownImpl2<IKpiDecoder, IKpiVideoWindow>
    {
        //(IKpiDecoder と IKpiVideoWindow のメソッド)
    };
    ```

    `KbKpiUnknownImpl<IKpiDecoder>` と IKpiVideoWindow から派生させただけでは、IKpiVideoWindow の側の QueryInterface・AddRef・Release が
    実装されないままになります（コンパイルできません）。

  - 本体は、IKpiVideoWindow を IKpiDecoder より先に解放します。
- 本体の親ウィンドウの中に描く（VIDEO_PARENT）：
  - 親ウィンドウ（トップレベルのウィンドウ）は本体が曲をまたいで同じものを使い、位置・大きさ・全画面・常に手前に表示・表示/非表示・閉じる・
    右クリックのメニュー・曲の切り替わりは、すべて本体と親ウィンドウが行います。プラグインは、映像を描く子ウィンドウを親ウィンドウの中に
    作るだけです。kbrunkpi.exe 経由のときは、kbrunkpi.exe が自分のプロセスに作った親ウィンドウが渡されます（プラグインから見れば同じです）。
  - タイトルは本体が付けますが（「Video - ファイル名 -」）、プラグインが決めることもできます。子ウィンドウにウィンドウ名を付けると
    （SetWindowText など）、本体はその名前をそのまま親ウィンドウのタイトルにします。付け方はプラグインの自由で、本体の付け方に合わせなくて
    かまいません（再生に使っている方式を添える、など）。後から変えてもかまいません（少し遅れて反映されます）。長すぎる分は切られます。
    名前が空なら、本体が付けます。演奏プラグインの子ウィンドウ（7-4）でも同じです。
  - 本体の約束：親ウィンドウは、IKpiDecoder を解放するまで消さず、作り直さず、子ウィンドウを別の親に付け替えません。
    子ウィンドウの中身を途中で作り直したいとき（曲ごとにレンダラーを替えるなど）は、返した子ウィンドウを入れ物にして、その中に作った子を
    作り直してください。トップレベルのウィンドウでないと動かないものは、自分のウィンドウ（WINDOW）で実装してください。
  - 子ウィンドウは、プラグインが自分で作ったスレッドで作り、そのスレッドでメッセージを処理し続けてください。CreateVideoWindow を呼んだ
    スレッドで作ってはいけません（本体のメインスレッドや、kbrunkpi.exe の Render を呼ぶスレッドのウィンドウになってしまいます）。
    CreateVideoWindow の中では、自分のスレッドに頼んで、できるのを待ちます。待つ時間には上限を付けてください。
  - 子ウィンドウだけをすぐに作って返し、時間のかかる準備（画像の読み込みなど）は後から続けてください。その間は黒い画面でかまいません。
    準備の間も、そのスレッドでメッセージを処理してください（kbbms は、画像を 1 枚デコードするごとに処理しています）。
    先に作っておいた描画用のウィンドウ（WS_CHILD）を、CreateVideoWindow で SetParent して親ウィンドウの子にしてもかまいません
    （kbdshow はこの形です。レンダラーを作り直さずに済みます）。
  - 子ウィンドウは次のように作ってください：
    - 隠したまま作る（WS_VISIBLE を付けない）。表示・非表示と大きさ（親ウィンドウのクライアント領域いっぱい）は親ウィンドウが決めます。
      プラグインは子ウィンドウ・親ウィンドウの表示や位置を変えないでください。
    - WS_DISABLED を付ける。マウスの操作（全画面にする・戻すなど）が親ウィンドウに届くようにするためです。
    - WS_EX_NOPARENTNOTIFY を付ける。親ウィンドウはプラグインとは別のスレッドで動いているので、作る・消すときに親ウィンドウへ
      同期のメッセージを送らないようにするためです。同じ理由で、親ウィンドウへ SendMessage しないでください。
    - WS_CLIPSIBLINGS を付ける（ギャップレスでは、前の曲と次の曲の子ウィンドウが同じ親ウィンドウの中に重なります。前に出すのは本体です）。
  - 親ウィンドウは子ウィンドウの大きさを待たない呼び方（SWP_ASYNCWINDOWPOS）で合わせます。WM_SIZE で、子ウィンドウの中に映像を置き直してください
    （縦横比を保つなら余白は黒く塗る）。子ウィンドウのスレッドは届いたメッセージをすべて処理してください（MsgWaitForMultipleObjects で待つなら、
    MsgWaitForMultipleObjectsEx に MWMO_INPUTAVAILABLE を付けるか、戻るたびに PeekMessage で全部取り出す。1 つずつしか取り出さないと、
    親ウィンドウからのメッセージが処理されずに残ることがあります）。
  - 親ウィンドウは、DPI の扱いが違う子ウィンドウも付けられるようにしています（kbrunkpi.exe は高 DPI に対応していません）。
  - 本体は、親ウィンドウの縦横比と大きさを KPI_MEDIAINFO の dwVideoWidth・dwVideoHeight から決めるので、映像があれば入れてください。
  - 本体は、返された子ウィンドウが渡した親ウィンドウの子であることを確かめてから使います。子ウィンドウは IKpiDecoder を解放するまでに
    消してください。親ウィンドウは消さないでください。
  - 本体はギャップレス再生のために次の曲を先に開くので、CreateVideoWindow が呼ばれても、まだ前の曲が鳴っていることがあります。
    いつ表示するかは本体が決めます（音が切り替わったときに、その曲の子ウィンドウを前に出します）。
- 自分のウィンドウを使う（WINDOW）：
  - CreateVideoWindow(NULL, …) が呼ばれたら、ウィンドウを隠したまま準備して TRUE を返してください。表示するのは SetVisible(TRUE) が
    呼ばれてからです（本体は、その曲の音が鳴り始めるときに呼びます）。先に開かれた次の曲のウィンドウが、前の曲の間に出ないようにするためです。
  - SetVisible・SetTopMost・SetWindowPosition は、待たない API で行ってください（ShowWindowAsync、SetWindowPos に SWP_ASYNCWINDOWPOS、
    自分のスレッドへの PostMessage など）。別のプロセスのウィンドウでも、相手が止まっているときに戻れます。
  - 閉じるボタンでは、できるだけウィンドウを隠すだけにして、次に SetVisible(TRUE) が呼ばれたらまた表示してください（本体の親ウィンドウや、
    演奏プラグインの自分のウィンドウ（7-4）と同じ動きです）。本体は閉じられたことを知らないので、次の曲・停止の後の再生・表示の設定を
    変えたときなどに、今までどおり SetVisible(TRUE) を呼びます。外部のアプリが閉じられて終了してしまう場合は、次の SetVisible(TRUE) で
    起動し直すか、何もしなくてかまいません。どの場合も、音のデコードは止めないでください。
  - 位置・大きさは、演奏プラグインの自分のウィンドウ（7-4）と同じ意味です。本体は、動画のウィンドウと同じ位置・大きさの設定を使います。
    従えるものだけ WINDOW_MOVE・WINDOW_SIZE を返してください。本体と同じ位置にしたくなければ、どちらも返さず、プラグインが自分で位置を
    覚えてください（本体は SetWindowPosition を呼びません）。
  - GetWindowPosition は、本体が、利用者の動かした位置を覚えるために時々呼びます（今は約 250ms ごと）。ウィンドウがまだない間・隠している間は、
    最後に SetWindowPosition で指示された位置を返してください（そうしないと、本体が覚えている位置が、準備中の値で上書きされます）。
  - 準備に時間がかかるとき（外部のアプリの起動を待つなど）は、指示を覚えておき、ウィンドウができてから反映してください。
    Seek などでウィンドウを作り直す作りの場合も、作り直した後に、覚えておいた指示（表示・位置・常に手前）を反映し直してください
    （kbzmdrive は、前に戻る Seek で ZMDRIVE.exe を起動し直すので、こうしています）。
  - ウィンドウの指示は Seek・Render と同時に呼ばれるので、Seek・Render の中でウィンドウのハンドルなどを作り直すなら、指示の側と排他して
    ください。排他の中では、値の読み書きと待たない API だけにしてください（プロセスやスレッドを待つ処理は、排他の外に置く）。
  - 外部のアプリが知らせてきたウィンドウのハンドルは、そのプロセスのウィンドウかを確かめてから使ってください（GetWindowThreadProcessId）。
  - 映像の大きさ（dwVideoWidth・dwVideoHeight）は、入れなくてもかまいません。大きさを変えられる（WINDOW_SIZE を返す）なら、
    本体の「動画サイズ」の倍率の指定に使われるので、入れてください。
- 再生位置・再生状態（PLAY_STATUS）：
  - SetPlayStatus で、本体が書く KPI_PLAY_STATUS の場所を受け取ります。プラグインは読むだけです。
  - dwPosition は、出力デバイスの位置から出した「いま聞こえている位置」です。再生速度を変えているときは、元の曲の位置に直した値です。
    PLAY_STATUS を返したデコーダの演奏中は、5ms ごとに更新します。シークのときも書きます。
  - 書くのは「いま鳴っている曲」の分だけです。ギャップレスで次の曲に移るときは、音が切り替わった時点で書き込み先が切り替わります。
    再生中に次の曲を開いたときは、次の曲の dwStatus を先に PLAYING にします。表示してよいかの判断には使わないでください。
  - Seek・Render は、聞こえる位置より先（先読みの分）に呼ばれます。単曲リピートで先頭に戻る Seek も、音が曲の終わりに着く前に呼ばれます。
    映像などを音に合わせるときは、Seek・Render が呼ばれた時機ではなく、dwPosition と dwStatus だけを見て動かしてください。
  - dwPosition は 5ms ごとにしか変わらないので、その間は実時間で補ってください（再生速度を変えているときは、dwPosition の進む速さも見る）。
  - 決まり：受け取った場所は、IKpiDecoder を解放した後は読めません（kbrunkpi.exe 経由では、読むと落ちます）。自分のスレッドから読むなら、
    解放までにスレッドを止めてください。スレッドが終わるのを待ちきれないことがある作り（7-3 のように、待つのをやめて先に進む）なら、
    解放のときに場所を忘れる処理（ポインタを NULL にする）と、スレッドが読む処理を排他してください（kbbms・kbdshow はこうしています）。
    古い仕組み（6-10）ではプラグインが共有メモリを持っていたので、この心配はありませんでした。
